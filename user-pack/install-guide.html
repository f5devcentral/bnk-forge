BNK Forge — Install Guide

Public registry edition  |  current-release distribution  |  registry: ghcr.io/f5devcentral
This guide walks you through installing BNK Forge from the public GitHub Container Registry. You download the install package, make a small configuration change, and run a single script. The images are public, so no registry login is required. The entire process takes under ten minutes on a fast connection; the first image pull may take a few minutes depending on bandwidth.

Prerequisites

  • Docker Engine 24+ — on macOS or Windows, Docker Desktop satisfies both this and the Compose requirement.
  • Docker Compose v2 (≥ 2.24) — verify with docker compose version.
  • ~5–10 GB free disk space — for images and persistent data volumes.
  • Network access to ghcr.io — outbound HTTPS (port 443) must be allowed.

Step 1 — Download & extract the package

You should have received a bnk-forge-<version>.tar.gz archive alongside this guide. Save it to a convenient location, then extract it:

$ tar xzf bnk-forge-<version>.tar.gz
$ cd bnk-forge-<version>

All subsequent commands are run from inside this directory.

Step 2 — Configure

Copy the example environment file and open it in your editor:

$ cp .env.example .env
$ nano .env   # or: vim .env / code .env

Set (or confirm) the following values:

Variable Value to set Notes
BNK_FORGE_REGISTRY ghcr.io/f5devcentral Points to the public registry.
BNK_FORGE_VERSION latest Rolling latest release. To pin a specific version, use its tag, e.g. 3.1.6.
POSTGRES_PASSWORD your choice Change from the default. Used for the internal database.
REDIS_PASSWORD your choice Change from the default. Used for the internal cache/queue.
MCP_PASSWORD match the admin password Must equal the password of the user in MCP_USERNAME. Credential the bundled MCP server uses to authenticate to BNK Forge; it must match a real BNK Forge user (the default MCP_USERNAME is admin, whose initial password is changeme). Leave it at changeme for the first boot so it matches the seeded admin account; it is re-read from .env on every boot, so after you change the admin password (Step 4) set this to the same value and re-run docker compose up -d (a plain docker compose restart does not re-read .env). Setting it to an independent secret before first login makes the MCP server 401 against the still-default admin credential.
Set strong passwords before first start
POSTGRES_PASSWORD and REDIS_PASSWORD replace well-known placeholder defaults, and they are baked in when the database and cache first initialize — get them right before running the installer, as they cannot be changed easily afterward. MCP_PASSWORD is different: it must always equal the password of the admin account it authenticates as, so leave it at the shipped changeme for first boot and rotate it together with the admin password afterward — it is re-read on every boot, so edit .env and re-run docker compose up -d to apply the new value (a plain docker compose restart does not re-read .env).

Step 3 — Install

Run the installer for your platform. It will pull the images and bring the full stack up. The first run may take a few minutes while images download.

Platform Command
macOS / Windows
(Docker Desktop)		 
$ ./install.sh --local
Linux server 
$ ./install.sh

When the installer finishes you will see:

✅ Installation complete!

Step 4 — First login

  1. Open the UI.
    Local install: https://localhost
    Server install: https://<server-ip>

  2. Accept the self-signed certificate warning.
    BNK Forge ships with a self-signed TLS certificate for initial setup. Your browser will show a security warning — click "Advanced" → "Proceed" (Chrome/Edge) or "Accept the Risk and Continue" (Firefox). This is expected.

  3. Log in with the default credentials:
    Username: admin  /  Password: changeme

    Change the admin password immediately
    The default password is well-known — change it as your very first action after login, via User menu → Change Password, before doing anything else.

  4. Sync the Module Library.
    Navigate to System → Module Library → Sync Modules to pull the current module catalogue from the registry.

  5. Create your first project.
    Navigate to Build → Projects → New Project to get started.

Verify the stack is healthy

All services should show healthy in the Compose status output.

Linux / server install:

$ docker compose ps

macOS / Windows (local mode):

$ docker compose -f docker-compose.yml -f docker-compose.local.yml ps

Every row in the STATUS column should read healthy. If any service is starting, wait 30 seconds and re-run — the backend performs a database migration on first start that takes a moment.

Logs shortcut
To follow all service logs in real time: docker compose logs -f

Updating to a newer build

Because BNK_FORGE_VERSION=latest is a rolling tag, updating is simple. From the install directory:

# Recommended — uses the installer for any migration steps:
$ ./install.sh          # Linux
$ ./install.sh --local  # macOS / Windows

# Alternative — manual pull and restart:
$ docker compose pull && docker compose up -d

If you pinned a specific build tag in .env, update BNK_FORGE_VERSION to the new tag before running the command above.

Before upgrading an older install to 4.0.0
If your .env predates this release, reconcile it first, or the upgrade will fail to pull or refuse to boot:
  • Registry & version. Set BNK_FORGE_REGISTRY=ghcr.io/f5devcentral (older packages pointed at a private org that no longer resolves), and replace any pinned BNK_FORGE_VERSION such as 3.0.1 with latest or a current tag like 3.1.6 — a stale pin pulls a tag that no longer exists.
  • Non-root artifact images. The container runner now refuses any image whose USER is root or a named user (e.g. USER nonroot). Rebuild your own runner images with a numeric USER 1000 before upgrading.
  • MCP service credential (from 4.0.0). Starting with 4.0.0 the backend refuses to boot in staging/production if MCP_SERVICE_PASSWORD is unset or still a shipped default. Set it to a real secret (the same value the MCP server receives as BNK_FORGE_PASSWORD) before upgrading, or the stack will exit at startup once that check is in the tree.

Uninstall

$ ./uninstall.sh

This stops and removes all containers and networks. Persistent volumes (database, etc.) are retained unless you pass --volumes — see ./uninstall.sh --help.

Troubleshooting

  • manifest unknown, or a pull that hangs or times out The images are public, so no login is required. Check that BNK_FORGE_REGISTRY is ghcr.io/f5devcentral and that the version tag exists, and that outbound HTTPS to ghcr.io (port 443) is allowed through any proxy or firewall.
  • Backend service not healthy Inspect the backend logs: 
    $ docker logs bnk-forge-backend --tail 80
    Common causes: wrong POSTGRES_PASSWORD in .env (must match what the database was initialised with), or a database migration that needs a moment to complete.
  • Port already in use (443, 8000, 8080, 5432, 6379) Stop the conflicting service, or adjust the port mappings in your .env file before running the installer. Common conflicts: a local PostgreSQL (5432), a local Redis (6379), or another reverse proxy on 443/8080.
