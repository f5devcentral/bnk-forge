BNK Forge — Install Guide

Private registry edition  |  customer-build distribution  |  registry: ghcr.io/f5devcentral
This guide walks you through installing BNK Forge from the private GitHub Container Registry. You will authenticate to the registry using the read-only bot credential you were provided, download the install package, make a small configuration change, and run a single script. The entire process takes under ten minutes on a fast connection; the first image pull may take a few minutes depending on bandwidth.

Prerequisites

  • Docker Engine 24+ — on macOS or Windows, Docker Desktop satisfies both this and the Compose requirement.
  • Docker Compose v2 (≥ 2.24) — verify with docker compose version.
  • Read-access token — the <READ_TOKEN> provided to you separately (see Step 1).
  • ~5–10 GB free disk space — for images and persistent data volumes.
  • Network access to ghcr.io — outbound HTTPS (port 443) must be allowed.

Step 1 — Authenticate to the registry

Credentials — handle with care
Your read-access token is provided separately (out-of-band). It is a GitHub PAT scoped to read:packages for the ghcr.io/f5devcentral registry. Do not share it, commit it to version control, or embed it in scripts. If you believe the token has been exposed, contact the person who gave it to you immediately.

Run the following command, replacing <READ_TOKEN> with the token you received. The bot username is fixed — use it exactly as shown:

$ echo '<READ_TOKEN>' | docker login ghcr.io -u jlcode-forgebot --password-stdin

Expected output:

Login Succeeded
Token stays cached
Docker stores the credential in your OS keychain (or ~/.docker/config.json). You only need to log in once per machine. If you later see a denied or unauthorized error during a pull, re-run the command above — the token may have been rotated. See the Troubleshooting section for details.

Step 2 — Download & extract the package

You should have received a bnk-forge-<version>.tar.gz archive alongside this guide. Save it to a convenient location, then extract it:

$ tar xzf bnk-forge-<version>.tar.gz
$ cd bnk-forge-<version>

All subsequent commands are run from inside this directory.

Step 3 — Configure

Copy the example environment file and open it in your editor:

$ cp .env.example .env
$ nano .env   # or: vim .env / code .env

Set (or confirm) the following values:

Variable Value to set Notes
BNK_FORGE_REGISTRY ghcr.io/f5devcentral Points to the private registry.
BNK_FORGE_VERSION customer-build Rolling latest build. To pin a specific build, use a tag like 3.0.1-cb.<sha>.
POSTGRES_PASSWORD your choice Change from the default. Used for the internal database.
REDIS_PASSWORD your choice Change from the default. Used for the internal cache/queue.
MCP_PASSWORD your choice Change from the default. Used by the MCP integration layer.
Change all three passwords
The defaults in .env.example are well-known placeholders. Replace POSTGRES_PASSWORD, REDIS_PASSWORD, and MCP_PASSWORD before running the installer — they cannot be changed easily after the stack first starts.

Step 4 — Install

Run the installer for your platform. It will pull the images and bring the full stack up. The first run may take a few minutes while images download.

Platform Command
macOS / Windows
(Docker Desktop)		 
$ ./install.sh --local
Linux server 
$ ./install.sh

When the installer finishes you will see:

✅ Installation complete!

Step 5 — First login

  1. Open the UI.
    Local install: https://localhost
    Server install: https://<server-ip>

  2. Accept the self-signed certificate warning.
    BNK Forge ships with a self-signed TLS certificate for initial setup. Your browser will show a security warning — click "Advanced" → "Proceed" (Chrome/Edge) or "Accept the Risk and Continue" (Firefox). This is expected.

  3. Log in with the default credentials:
    Username: admin  /  Password: changeme

    Change the admin password immediately
    The default password is well-known. Go to User menu → Change Password as your very first action after login.

  4. Sync the Module Library.
    Navigate to System → Module Library → Sync Modules to pull the current module catalogue from the registry.

  5. Create your first project.
    Navigate to Build → Projects → New Project to get started.

Verify the stack is healthy

All services should show healthy in the Compose status output.

Linux / server install:

$ docker compose ps

macOS / Windows (local mode):

$ docker compose -f docker-compose.yml -f docker-compose.local.yml ps

Every row in the STATUS column should read healthy. If any service is starting, wait 30 seconds and re-run — the backend performs a database migration on first start that takes a moment.

Logs shortcut
To follow all service logs in real time: docker compose logs -f

Updating to a newer build

Because BNK_FORGE_VERSION=customer-build is a rolling tag, updating is simple. From the install directory:

# Recommended — uses the installer for any migration steps:
$ ./install.sh          # Linux
$ ./install.sh --local  # macOS / Windows

# Alternative — manual pull and restart:
$ docker compose pull && docker compose up -d

If you pinned a specific build tag in .env, update BNK_FORGE_VERSION to the new tag before running the command above.

Uninstall

$ ./uninstall.sh

This stops and removes all containers and networks. Persistent volumes (database, etc.) are retained unless you pass --volumes — see ./uninstall.sh --help.

Troubleshooting

  • denied: denied or unauthorized: unauthenticated during pull Your docker login session has lapsed, or the token does not have the read:packages scope. Re-run Step 1 with your current token. If the problem persists, contact the person who issued the token.
  • Backend service not healthy Inspect the backend logs: 
    $ docker logs bnk-forge-backend --tail 80
    Common causes: wrong POSTGRES_PASSWORD in .env (must match what the database was initialised with), or a database migration that needs a moment to complete.
  • Port already in use (443, 8000, 8080, 5432, 6379) Stop the conflicting service, or adjust the port mappings in your .env file before running the installer. Common conflicts: a local PostgreSQL (5432), a local Redis (6379), or another reverse proxy on 443/8080.
