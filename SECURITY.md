# Security Policy

## Supported Versions

Security fixes land on `main`. Only the latest released version is supported —
please upgrade before reporting an issue against an older release.

| Version | Supported |
| ------- | --------- |
| Latest release on `main` | :white_check_mark: |
| Any earlier release | :x: |

## Reporting a Vulnerability

Please do **not** open a public GitHub issue for a security vulnerability.

Use whichever of these fits you:

1. **GitHub Private Vulnerability Reporting** — the "Report a vulnerability"
   button under this repository's **Security** tab. Preferred for issues
   specific to this project.
2. **F5 SIRT** — for anything affecting F5 products or services, email the F5
   Security Incident Response Team at **f5sirt@f5.com**, following F5's
   [vulnerability reporting guidelines](https://www.f5.com/support/report-a-vulnerability).
   F5 SIRT publishes a PGP key for encrypted reports.
3. **F5 customers with an active support contract** should contact F5 Technical
   Support through their normal channel.

Please include:

- The affected component and version (`VERSION` file, or the image tag).
- A description of the vulnerability and its impact.
- Reproduction steps or a proof of concept.
- Any suggested mitigation.

## What to Expect

- Acknowledgement of your report within **5 business days**.
- An assessment and, where the issue is confirmed, a remediation plan.
- Impact communicated using CVSS v3.1.
- Attribution in the release notes if you would like it.

Please give us a reasonable opportunity to ship a fix before disclosing
publicly. F5's overall vulnerability response policy is documented in
[K4602](https://my.f5.com/manage/s/article/K4602).
