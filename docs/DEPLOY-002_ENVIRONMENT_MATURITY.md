# DEPLOY-002: Environment Maturity Ladder

**Status:** Complete
**Version:** 2.11.0

---

## Purpose

Define clear expectations for each deployment environment so teams know
what is guaranteed at each tier.

---

## Environment Tiers

### Tier 0: Local Development

| Attribute | Value |
|-----------|-------|
| **Purpose** | Feature development and debugging |
| **Stack** | `docker compose -f docker-compose.local.yml up` |
| **Networking** | Bridge mode (macOS/Windows compatible) |
| **Database** | Fresh per `make clean && make install` |
| **Data** | Seed data only (admin user, built-in modules) |
| **TLS** | Self-signed (auto-generated by proxy) |
| **Monitoring** | Container logs (`make local-logs`) |
| **Backups** | None |
| **SLA** | None — expect breakage |
| **Who runs it** | Individual developer |

**Guarantees:** App starts. Login works. Core CRUD works.

### Tier 1: CI Pipeline

| Attribute | Value |
|-----------|-------|
| **Purpose** | Automated testing and build verification |
| **Stack** | Docker Compose on GitHub Actions runner |
| **Database** | Ephemeral (destroyed after run) |
| **Data** | Seed data + test fixtures |
| **Tests** | Lint → Unit → Component → Integration → E2E Tier 1 |
| **Duration** | Under 10 minutes total |
| **Artifacts** | Test reports, Docker images, coverage |

**Guarantees:** Build succeeds. All tests pass. No regressions.

### Tier 2: Staging

| Attribute | Value |
|-----------|-------|
| **Purpose** | Pre-production validation with real infrastructure |
| **Stack** | Docker Compose on dedicated server (host networking) |
| **Database** | Persistent (migrated via Alembic) |
| **Data** | Production-like (real clusters, real modules) |
| **TLS** | Self-signed or Let's Encrypt |
| **Monitoring** | Container health checks + log aggregation |
| **Backups** | Daily automated (postgres-backup container) |
| **SLA** | Best-effort, may be reset without notice |
| **Who runs it** | Engineering team |

**Guarantees:** Mirrors production topology. Deployment process validated.
Health checks pass. E2E smoke tests pass post-deploy.

### Tier 3: Production

| Attribute | Value |
|-----------|-------|
| **Purpose** | Real user workloads |
| **Stack** | Docker Compose on production server (host networking) |
| **Database** | Persistent, backed up daily (7-day retention) |
| **Data** | Real user data |
| **TLS** | Valid certificate (Let's Encrypt or CA-signed) |
| **Monitoring** | Container health + log aggregation + alerting |
| **Backups** | Daily automated + pre-upgrade snapshot |
| **SLA** | Business hours support |
| **Who runs it** | Operations team |

**Guarantees:** `upgrade.sh` preflight checks pass. Health gates pass
post-deploy. Rollback path tested. Backup verified before upgrade.

---

## Promotion Path

```
Local → CI → Staging → Production
  ↑       ↑       ↑         ↑
  dev    PR merge  manual   manual
         gate     deploy    deploy
                  + smoke   + checklist
```

### Gate Requirements

| Gate | Required | Automated |
|------|----------|-----------|
| Local → CI | PR created | Yes |
| CI → Staging | CI passes + PR approved | Semi (manual deploy) |
| Staging → Prod | Smoke tests pass + DEPLOY-001 checklist | Manual |

## Environment Variables by Tier

| Variable | Local | CI | Staging | Production |
|----------|-------|----|---------|------------|
| `LOG_FORMAT` | text | json | json | json |
| `LOG_LEVEL` | DEBUG | INFO | INFO | INFO |
| `REQUIRE_AUTH` | false | true | true | true |
| `DEBUG` | true | false | false | false |
| `CORS_ORIGINS` | * | localhost | staging URL | prod URL |
